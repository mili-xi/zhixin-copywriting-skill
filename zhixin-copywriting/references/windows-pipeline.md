# Windows 批处理设计参考

先用一篇稿件验证人工流程，再把需要批量执行的阶段替换为脚本。每个客户使用独立工作区，发布目标由用户在运行时授权。

| 阶段 | 交接产物 | 实现要点 |
| --- | --- | --- |
| 采集 | 带来源的商品事实和缺失项 | 优先使用简报和授权资料。需要 Playwright 时，串行使用该项目的独立浏览器配置，采集后释放。遇登录或验证时交给授权用户处理。 |
| 整理 | 精简简报与选题 | 核对商品名称、读者、规格和品牌约束。只保留获准使用的资料。 |
| 写稿 | `article.md` 与 `review.md` | 按客户约束写稿，逐条复核重要主张。需要配图时核实授权、替代文本和平台封面要求。 |
| 交付 | 本地稿件及按需生成的回执 | 默认交付本地。导入与发布分别取得授权，按 [MCP 接入说明](zhixin-mcp.md) 查询既有任务。 |

浏览器采集完成并释放配置后，再并发处理可独立执行的文本任务。按供应商限额设置并发，按媒体账号或桌面执行器控制投递顺序。

批处理可用 `runs.jsonl` 记录任务 ID、稿件版本、阶段、时间、错误码和回执 ID。由单个写入者或事务维护状态。分别记录已定稿、已导入、已提交、审核中、已公开、结果未知和失败。按客户、稿件版本与目标账号查重，发布结果未知时先对账。

配置 Windows 任务计划前，先确认脚本的演练模式是否会访问外部服务或写缓存。设置工作目录、运行账户、日志和进程互斥，验证定期触发时浏览器配置的占用情况。路径从工作区解析，稿件用 UTF-8。Windows PowerShell 5.1 中含中文的 `.ps1` 用 UTF-8 BOM。
